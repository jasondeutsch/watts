# Eval cases

Copy [TEMPLATE.md](TEMPLATE.md) to `<case-id>/CASE.md`. Store the starting project in `<case-id>/project/` and independent verification materials in `<case-id>/verification/`.

Choose cases representative of the team's Go work: new functionality, bug fixes, maintenance, integration, testing, and ambiguous requirements. Avoid selecting only tasks that already perform well.

A case must specify its exact request, initial project, acceptance criteria, change boundaries, verification procedure, and intervention policy. Clarifications should have predefined answers where possible so configurations receive equivalent information.

Keep verification materials outside the evaluated agent's project when they should remain hidden. Maintain starting projects without credentials or external production dependencies. Document any local fixtures or network requirements.

Freeze selected cases for a comparison period. Record content digests or immutable revisions in run records; a path alone does not identify a starting project version. Templates and this README are not benchmark cases.
